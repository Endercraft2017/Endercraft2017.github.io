This is a bounded component update to the existing AFK³ homepage and OTOM bridge. It preserves the cyan/blue parent brand, two buying routes, E-Z product card, forms, source attribution and SendFox endpoint.

## Design decisions and skills actually used

- [Genjutsu](https://github.com/AThevon/genjutsu): read `cast`, `css-native` and `motion-principles`. Native APIs fit the existing vanilla stack; the active screen stays sharp while neighboring screens recede. Auto transitions use 700 ms, manual pointer transitions 380 ms and keyboard/reduced-motion changes are immediate. The approved 3D direction and existing private-preview preference answer the routine design gates.
- [Taste Skill](https://github.com/Leonxlnx/taste-skill): applied its existing-brand and single-section exceptions. Kept the surrounding typography, palette and buying paths; used genuine UI instead of generic illustrations. No new random visual direction was drawn.
- [Hallmark](https://github.com/Nutlope/hallmark): applied component scope and a control-state review. Preserved the existing system and supplied focus, pressed, disabled, loading and failure feedback where applicable. A delivery-method explanation has no network loading or success state. Browser-only Hallmark scripts were not run; the managed Sites/CUA workflow supplies browser QA.
- [Brag](https://github.com/latent-spaces/brag): read the product planning/story guidance and used its real-product and readable-hold principles. The carousel leads with Attendance, Draft Payroll and Employee Mobile, then Warehouse, Production and Sales. This does not claim that a Brag/Hyperframes launch video was rendered.

## What changed

- Shared `product-showcase.css/js` controls six source-rendered screen captures on the homepage and `/products/otom`.
- `afk-showcase.css` supplies the parent brand and existing layout conventions. Portrait images retain their aspect ratio; the frame is not a re-created ERP screen.
- Autoplay runs only while meaningfully visible, and has Pause/Play and manual controls. Focus and manual interaction stop rotation until explicitly restarted. Reduced motion disables auto/spatial transitions.
- `afk-showcase.js` carries an allowlisted selected screen to the existing inquiry route while retaining referral/campaign parameters.
- A small `script.js` addition suggests a matching message only for `intent=otom` and a known screen, only when the message is empty. It preserves restored or already written text.
- `home-process.js` makes the existing desktop delivery map manually selectable. It explains real discovery, implementation and handover steps, without another automatic loop.
